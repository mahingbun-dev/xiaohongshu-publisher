# 可执行计划书：xiaohongshu-publisher 增加「对标分析」环节

> 生成：2026-09-29 ｜ 状态：已执行（遗留：实时抓取首跑校准，见 §8）

## 1. 一句话目标

给 `xiaohongshu-publisher` skill 增加发布前的「对标分析」阶段（新阶段 0.5）：用 Ego Lite 实时搜索同主题高赞笔记，提炼标题钩子模式、封面形式、话题池、正文结构，以硬规范反哺文案与配图生成。成功标准：跑通一个真实系列后，每篇标题都能指出对应的已验证爆款模式，封面风格选择有对标结论支撑。

## 2. 背景

skill 现状（`/Users/sunny/code/xiaohongshu-publisher/publisher/SKILL.md`）：文案基于用户素材 + 固定写作规范（阶段 2），配图基于三套固定卡片风格预设（阶段 4），**没有对标环节**，生成质量依赖模型通用能力。用户要求：生成图片和文案前，先分析当前小红书同类帖子如何引流、吸引人、获得高点赞收藏。

可行性已核实：发布链路已在用 Ego Lite 登录态小红书会话（`references/publish-recipe.md` §0 有登录判据），同一会话可打开 `xiaohongshu.com/search_result` 搜索并提取笔记卡片数据；公开运营资料确认标准打法即「同赛道搜关键词 → 取近期点赞 Top → 拆标题/封面/排版」（来源见 §10）。

## 3. 访谈结论（已确认决策）

| 维度 | 结论 |
| --- | --- |
| 目标 | 生成前做对标分析，把高赞/高收藏帖的引流打法提炼成可执行规范反哺文案+配图 |
| 数据来源 | **Ego Lite 实时搜小红书**（复用已登录会话，搜关键词→按热门/最多点赞排序→抓 Top 笔记的标题、封面、点赞、收藏、评论、话题）。不用第三方付费平台（千瓜/新红） |
| 沉淀形式 | 系列目录下 `benchmark-report.md`（人读的分析报告）+ `benchmark.json`（结构化结论，供后续阶段程序化引用） |
| 分析时机 | **每系列一次**，插入为「阶段 0.5」（访谈确认主题后、写文案前），全系列共用结论 |
| 文案反哺 | **硬规范逐条对照**：每篇标题必须套用对标提炼出的某个已验证钩子模式并在 copy.md 标注模式名；话题标签从对标话题池选取；正文结构参考高赞帖的分段/emoji/互动引导写法 |
| 配图反哺 | **封面形式对标**：分析 Top 笔记封面形式（大字报/实拍/图表卡片）、信息密度、配色倾向，映射到 build-cards 风格 token（必要时新增预设）；内页保持现有设计规则不动 |
| 范围边界 | **不含发布后复盘**（不回看自己笔记数据），留作后续迭代 |

## 4. 待定项与默认假设

| 待定项 | 默认假设 | 再确认时机 / 负责人 |
| --- | --- | --- |
| 采样规模 | 每系列搜 1~2 个关键词、取 Top 10~20 篇有效样本；<5 篇视为样本不足触发降级 | 实跑时看搜索结果质量，可调 |
| 「高赞」判定 | 相对值：取搜索结果按点赞排序后的头部，同时记录收藏/点赞比（收藏>点赞 = 干货型信号） | 实跑时按赛道数据量调整 |
| 降级策略 | 抓取失败或样本不足 → 降级 WebSearch 公开资料 + 请用户提供对标笔记链接，报告标注降级来源 | 触发时告知用户 |
| 新增卡片风格预设 | 仅当对标结论与现有三套风格（tech-dark/paper-light/warm-life）都不匹配时才新增 | 阶段 4 实跑时决定 |

## 5. 范围

- **做**：
  1. `references/benchmark-recipe.md`——Ego Lite 搜索抓取配方（URL 格式、排序筛选、笔记卡片 DOM 提取、登录判据复用、已踩坑记录），模式同 `publish-recipe.md`
  2. `scripts/scrape-benchmark.mjs`——抓取脚本（输入：关键词列表+输出路径；产出：原始样本 `benchmark-samples.json`），失败时按配方手动兜底，沿用「脚本优先、配方兜底」惯例
  3. SKILL.md 新增**阶段 0.5 对标分析**：搜索 → 抓取 → 模型分析归类（标题模式/封面形式/话题池/正文结构/互动基准）→ 写 `benchmark-report.md` + `benchmark.json`
  4. SKILL.md 阶段 2（文案）加硬规范：标题套模式并标注、话题从池选取
  5. SKILL.md 阶段 3/4（配图）加封面结论引用；视觉验收清单加「封面与对标结论一致」检查项
  6. 总流程图更新：`需求确认 → 对标分析 → 目录与 manifest → 文案 → 配图 → 视觉验收 → …`
- **不做**：发布后数据复盘；第三方数据平台接入；内页版式改动；每篇单独对标。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 小红书搜索页改版/DOM 变化 | 抓取脚本失效 | 配方与脚本分离；配方记录替代提取路径（snapshot 驱动）；降级到 WebSearch + 用户对标 |
| 搜索结果受个性化推荐影响，样本代表性偏差 | 提炼的模式不通用 | 用排序筛选（最多点赞）+ 记录采样时间与关键词；报告注明样本口径 |
| 频繁抓取触发风控 | 账号受限 | 每系列只抓 1~2 次、单次 ≤20 篇、只读不互动；配方中明确禁止高频重试 |
| 分析结论空泛（「标题要有钩子」式废话） | 反哺无效 | benchmark.json 的模式条目必须带样本例句 + 样本量 + 互动中位数，无数据支撑的结论不写入 |
| 标题硬规范与 20 字限制/用户素材冲突 | 文案质量下降 | 规范写明「模式为形、素材为实」：套模式不得虚构用户素材外内容；冲突时保留素材事实并在报告标注 |
